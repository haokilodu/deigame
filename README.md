# DE&I 経営ゲーム シミュレーター

ボードゲーム「DE&I 経営ゲーム」の**補助アプリ**です。ゲーム本体はカードとコインで進め、このアプリは採用結果の入力と、手計算が面倒な部分（チーム仕事力・借金）を引き受けます。

**公開先** https://haokilodu.github.io/deigame/

---

## まず触ってみる

| URL | 用途 |
|---|---|
| https://haokilodu.github.io/deigame/ | 通常 |
| https://haokilodu.github.io/deigame/?reset | **必ず最初から始まる**。研修で配るのはこちら |

`?reset` を付けると保存状態を破棄して2名選択の画面から始まります。研修で前の参加者のデータが残ったまま次の人に渡る事故を防ぐためのものです。

---

## 構成

```
deigame/
└── index.html   ← これ1枚ですべて（約1,200行 / 84KB）
```

**ビルド不要・依存ライブラリゼロ**です。`index.html` をブラウザで開けばそのまま動きます（`file://` でも可）。CSS・JS・SVGアイコンもすべてこの1ファイルに入っています。

`main` ブランチに push すると GitHub Pages が自動で再ビルドします。通常1〜2分、混雑時は10分ほどかかることがあります。

## 画面の構成

**フェーズA** … 80人の人財から最初の2人を選ぶ

**フェーズB** … 3つのタブで進行

| タブ | 内容 |
|---|---|
| 🃏 ソリューション | 37枚から実施するものを選ぶ。選ぶと能力アップの演出が出る |
| 👥 メンバー | 人財の採用。**価値観と仕事力は伏せられている**（後述） |
| 💰 おかね | 借金の帳簿と、1期のお金の流れ |

画面上部のスコアボードは `position: sticky` で固定され、📊ボタンから組織の詳細モーダルが開きます。

## データ

`index.html` の 588行目あたりに直書きしています。

```js
const MEMBERS  = [...]   // 人財80人
const POLICIES = [...]   // ソリューション37枚
const VALUE_DESC = {...} // 5つの価値観の説明
```

**元データはGoogleスプレッドシートです。** 人財カードの一覧・バランス設計・ガチャ要素の管理はすべてそちらで行い、このファイルへは生成して貼り付けています。直接編集するとスプレッドシートと食い違うのでご注意ください。

### 人財データの形

```js
{ "name": "本田 琴音", "kana": "Honda Kotone", "icons": ["L"], "base": 1 }
```

`icons` は価値観（L=くらし / K=キャリア / G=グローバル / U=ユニークネス / F=フェア）、`base` は仕事力（1〜5）です。

**自己紹介（履歴書）は意図的に入れていません。** 物理カードに印刷されており、プレイヤーはそちらを読んで判断するためです。アプリは採用結果の入力役に徹しています。

### ソリューションデータの形

```js
{ "name": "フレキシブルワーク", "icons": ["L","K"], "cost": 2,
  "fx": ["recruit","shield"], "boost": 2, "desc": "時短勤務やフレックスなど..." }
```

`cost` はコイン、`fx` は効果（recruit=採用 / shield=離職防止 / promote=昇進）、`boost` は仕事力の強化値です。

## 主なルールと実装

### チーム仕事力

```
Σ(各メンバーの仕事力 + 価値観が1つでも一致するソリューションの boost) + 社長2
```

社長は常に在籍し、仕事力2で離職しません。

### 採用（ブラインド方式）

人財をタップ → 「この人財でよろしいですか？」→ はい、で判定します。

- その人財の**すべての価値観**が、実施中ソリューションの「採用」効果でカバーされていれば**成功**
- 1つでも欠けていれば**失敗**。何も起こらないが、価値観と仕事力だけ明らかになる
- 失敗した人財にも**再チャレンジ可能**（ソリューションを増やしてから）

一覧の並び順はセッションごとにシャッフルしています。`MEMBERS` が価値観順に並んでいるため、そのまま出すと位置から中身を推測できてしまうからです。同じ理由でメンバー画面に価値観フィルタは置いていません。

### 借金

ルールは `260905_DEI経営ゲーム.pptx`（スライド61〜64・170）に基づきます。

- 借入は**2の倍数**、上限**10コイン**
- 返済は借入額の**1.5倍**（2借りたら3返す）。部分返済可
- 給料が払えない場合は強制借金（不足分を2の倍数に切り上げ）
- ゲーム終了時に返済できなければ敗北

元本を常に偶数に保つ実装にしているため、1.5倍しても必ず整数になります。

### 1期のお金の流れ

おかねタブに、ゲームの5ステップ順で表示しています。

```
① 収入          +N   チーム仕事力
② ソリューション   —    買うときに支払い
③ 離職          —    サイコロ判定
④ 採用・昇進      —    昇進させるときに支払い
⑤ 給料          −N   メンバー人数 × 1
```

金額を出すのは①と⑤だけです。②と④はその場で支払うため、事前の見積もりに含めると混乱します。昇進コストも含めていません。

## 状態の持ち方

`sessionStorage`（キー `dei-sim-v2`）に保存しています。

- **同じタブでリロードしても復帰**する
- **タブを閉じる／開き直すとリセット**される
- `?reset` で強制リセット（パラメータは直後にURLから除去されるので、以降のリロードは通常どおり復帰します）

`localStorage` は使っていません。研修で状態が残り続けるのを避けるためです。

## 実装していないこと

現時点で未実装の機能です。

- **ターン管理**（第1〜5期の進行・参加者のターン状況の把握）
- **テナント管理**（複数グループ・複数プレイヤーの管理）
- **QRコードによるカード読み込み**
- 本格リリース版の UI/UX

おかねタブは期を持たない作りにしてあります。ターン管理が実装されたら、そちらに寄せてください。

このアプリは現在**1組織ぶんの計算機**で、他プレイヤーの概念がありません。複数プレイヤーを扱うには作りを広げる必要があります。

## 編集するときの注意

- データ部（`MEMBERS` / `POLICIES` / `VALUE_DESC`）は**スプレッドシートからの生成物**です。直接書き換えないでください
- 人財の自己紹介は**68〜80字**で設計されています（カードの印刷レイアウトの都合）
- **publicリポジトリ**です。APIキーやパスワードは置かないでください
